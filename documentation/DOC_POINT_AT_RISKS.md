# Risks and Open Questions

Version: 0.3 (draft)
This is a living document. Resolved questions move into DOC_POINT_AT_PROCESS.md and are noted in the change log at the bottom.

## Known failure modes

1. **Proxy optimisation.** Achieving a measurable stand-in (no violence) while destroying the real goal (human flourishing). Mitigation: hard constraints (consent, freedom, reversibility) that are never traded away; second and third order effects examined in proportion to risk.
2. **Swarm consensus.** Agents tend to agree and drift into confident, uniform conclusions. Mitigation: adversarial review by someone other than the author, differently prompted agents, and adversarial traversal (see open questions).
3. **Speculative downstream effects.** Second and third order effects quickly become guesswork. Mitigation: scrutiny scales with uncertainty and irreversibility, not applied blindly to well-proven assumptions.
4. **Whose values define the goal?** If one group's definition of "peace" is baked in, the project is quietly political. Unresolved.
5. **Scope creep.** The project is already larger than anything its author has built. Mitigation: build only the recursive unit first and test it on small tasks.
6. **Process that does not scale.** The same unit may not span a sandwich to world peace. The core assumption could simply be wrong.
7. **False or fabricated reports.** Humans can report actions they did not take, or pass off replies generated by another AI. Mitigation: verification levels; irreversible steps require higher-level or multiple independent inputs. Not fully preventable with current tools.
8. **Humans dropping out.** Because the handoff line follows capability, human involvement shrinks as agent tools improve. This may conflict with the goal of people feeling both the power and responsibility of democracy. Needs a safeguard outside the leaf rule.
9. **Stale tasks.** Nodes rest on facts that change. Mitigation: re-check on focus, and record assumptions and dates on each split.
10. **Lens bias.** The lens someone focuses through shapes the split, so one perspective could dominate a branch. Mitigation: adversarial review, and re-splitting through other lenses when results disappoint.
11. **Locked-in goals.** Goals, subgoals or tasks persist because nobody questioned them, although they would be argued away with real scrutiny. Mitigation: adversarial traversal (open question).

## Open questions

### Structure and lenses
- **Adversarial traversal:** adversarial agents should continually walk existing goals, subgoals and tasks and debate whether each is actually needed, so the system does not lock in on nodes that would be argued away with real scrutiny. Open: when they run, how a node is challenged, and what it takes to close or keep it.
- How topic lenses are defined later: free labels, a curated set, or embedding clusters. (Role views are decided: see DOC_POINT_AT_PROCESS.md 2.3.)
- How "also serves" links are created and validated.
- How assumptions on a split are recorded so they can be checked mechanically.
- Which actions should stay with humans regardless of capability, if any?
- Which verification level does each kind of downstream step require?

### Process and governance
- How top-level values and hard constraints are chosen, and by whom, so the framing is not one group's politics.
- How contributors are identified. Version 0.1 of the software trusts a free-text actor name; abuse needs a real answer before the tree is opened widely.
- How many differently prompted agents from different people contribute without degrading quality.

## Proposed first tests

1. **Sandwich test.** Run the process on "make a sandwich this morning". If it feels bureaucratic, the process is broken. (The example data shows the expected shape: one node, marked a leaf at once, done.)
2. **Awkward-task test.** Take the task from the existing plan tiers that fits worst and force it through the unit.
3. **Mid-tree entry test.** Start an agent at a random mid-level node and check it can move both up and down.
4. **Adversarial test.** Submit a plausible but harmful plan (the "enslave everyone for peace" pattern) and check that review catches it.
5. **Human leaf test.** Have a real person execute a human leaf, report back, and check the bounce-back and verification levels work.
6. **Scale-up** only after the above pass: try a genuinely large task.
